# Packagist first-publish verification

Issue: <https://github.com/link-foundation/package-registry-manager/issues/88>

The reported root cause was unconditional manual hook handling, secret-name-only
API handling and a generic submission browser step before discovery. Both plans
now dispatch one Packagist engine. The Rust crate embeds byte-identical sources
and controls its own Browser Commander page through a private stdin protocol.
Node/npm were already required for the pinned gh-manager transport. Only source
code is placed in the temporary program file; credentials never enter it.

The regression `Packagist hook inspects GitHub instead of unconditionally
returning a manual prerequisite` failed on the original implementation because
no inspection occurred. It now passes. Local logs are retained under ignored
`ci-logs/`; generated profiles, dependency trees and credentials are not committed.

Public Packagist ingests VCS tags. This change does not configure Private
Packagist artifact publishing or upload package artifacts. OAuth grants requiring
approval, credentials requiring user authentication and missing GitHub permissions
remain explicit incomplete outcomes; pressing Enter never establishes success.
