# Unpublished packages across link-assistant, link-foundation and linksplatform

Source: [`package-registry-manager`](https://github.com/link-foundation/package-registry-manager) account inspection (`inspect` logic) with public registry lookups.
Repositories copied from [`deep-foundation`](https://github.com/deep-foundation) are **excluded** from the main results and are listed separately in the appendix.

## Scope and method

- Organizations: [`link-assistant`](https://github.com/link-assistant), [`link-foundation`](https://github.com/link-foundation), [`linksplatform`](https://github.com/linksplatform).
- Archived repositories and forks are skipped, matching the account-scan default.
- Every supported manifest is discovered (`package.json`, `Cargo.toml`, `pyproject.toml`/`setup.py`, `*.csproj`, `pom.xml`, `composer.json`, `go.mod`, Dockerfiles, and others).
- Each publishable package is looked up on its public registry. **Unpublished** means the package name was not found on the registry at scan time.
- Copy detection: compared repository names with `deep-foundation`, then verified with identical HEAD commits, shared commit history, tree/file similarity, and README/package metadata. All 99 same-name repositories in `link-foundation` were confirmed as copies. No exact-HEAD copies were found in `link-assistant` or `linksplatform`; the five same-name `linksplatform` repositories are independent and stay in scope.
- Large repositories (`formal-ai`, `hive-mind`, `router`, `meta-sovereign`) were inspected with a partial clone limited to manifests and workflows.

## Reproduce

The canonical account scan is available in both CLIs:

```sh
cd js
node src/cli.mjs inspect --org link-assistant --format json > link-assistant.json
node src/cli.mjs inspect --org link-foundation --format json > link-foundation.json
node src/cli.mjs inspect --org linksplatform --format json > linksplatform.json
```

For this report, the same inspection code was run against shallow clones (API-based snapshots and partial clones for the largest repositories) to stay within GitHub API rate limits while preserving identical manifest discovery and registry lookups.

### Tooling changes from this session

- `js/src/publisher-form.mjs` now submits a prefilled sign-in form automatically for PyPI, npm web login, crates.io GitHub login, NuGet, credential pages, and repository repair. Autofilled values dispatch the input events that enable submit buttons (including npm's "Sign In"), never reads credential values, and announces passkey/2FA and unrecognized-device email confirmation instead of silently waiting.
- `js/src/workflow-inputs.mjs` reads `workflow_dispatch` inputs and retries a failed `gh workflow run` with declared defaults or the first choice option. This fixes the HTTP 422 for `bump_type` in `browser-commander/python.yml` and also supplies `release_mode`/`bump_type` for `js.yml`.
- The automated browser closes extra restored tabs at launch and keeps one working tab, removing accumulated `about:blank` pages; extension mode closes its own tab. It compares the working page by identity and URL so a Playwright wrapper is never closed as an extra tab, and the URL fallback ignores `about:blank` so restored blank tabs are not mistaken for the working page ([#92](https://github.com/link-foundation/package-registry-manager/pull/92)).
- npm security-key approvals are automated: the tool checks the 5-minute cooldown box and clicks “Use security key”; Touch ID or the physical key remains the only manual step.
- Visible automated browsers start maximized on Chromium (even when the profile saved small bounds) and Firefox; headless launches keep their default size.
- Coverage: `js/test/publisher-dom.test.mjs`, `js/test/workflow-inputs.test.mjs`, `js/test/page-cleanup.test.mjs`, and `js/test/publisher-signin.test.mjs`.
